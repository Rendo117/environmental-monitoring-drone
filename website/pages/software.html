Software

The software has three parts in three languages. Each runs where its timing requirements are met: C++ on the microcontroller for the 4 ms control loop, Python on the Raspberry Pi for networking and unit conversion, and Java on the operator's computer for the user interface.

Flight controller

Every 4 ms the loop runs through the same steps:

  1. read the four command pulses captured by the pin-change interrupt;
  2. read 14 bytes from the MPU-6050;
  3. update the complementary filter;
  4. run the arming state machine;
  5. compute the rate set-points;
  6. run the PID;
  7. mix the outputs to four motors;
  8. compensate for battery sag;
  9. generate the four ESC pulses.

Every 25th loop it also reads the gas sensor and sends a telemetry frame.

Build and test without hardware

# Arduino IDE: open firmware/flight_controller/flight_controller.ino, board "Arduino Uno", upload.
# Host-side logic test with a mocked Arduino API:
cd firmware/host_test
g++ -std=gnu++17 -I. -x c++ main.cpp -o fc_test && ./fc_test

Raspberry Pi bridge

bridge.py signs in to Firebase with its own account. It polls the command node ten times a second and turns each stick value v ∈ [0, 100] into a pulse of 1000 + 10v µs with the DMA-timed pigpio library. It also parses the flight controller's frames, verifies the checksum, converts gas and radiation readings to physical units and writes them back. If no new command arrives for one second, it stops the pulses, and the flight controller treats that as a lost link.

sudo apt install pigpio python3-pigpio python3-serial python3-requests
sudo systemctl enable --now pigpiod
cd raspberry-pi && cp config.example.ini config.ini   # fill in Firebase details
python3 bridge.py --simulate      # try it without any hardware
python3 test_sensors.py           # unit tests of the conversions

Ground station

A single Java application with no third-party dependencies. It authenticates with Firebase, sends stick commands as a 5 Hz keep-alive, and shows the telemetry with its uncertainty. It can record everything to CSV. An offline demo mode simulates the drone, so the interface can be tried without an account.

cd ground-station
./build.sh              # or build.bat on Windows
java -jar build/ground-station.jar

Firebase

The 2022 database could be read and written by anyone who knew its address. The new security rules require a signed-in account. Only operators may write commands, and only the aircraft may write telemetry. Each stick value must be a number from 0 to 100. Set-up takes about ten minutes on the free plan, as described in firebase/README.md.

/drones/drone1/command          {roll, pitch, yaw, throttle, seq, mode, sentAt}
/drones/drone1/telemetry/latest {status, roll_deg, …, gas_lpg_ppm, radiation_usv_h, …}
/drones/drone1/telemetry/history/<id>   (1 Hz log)
